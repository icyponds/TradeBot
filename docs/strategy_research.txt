1) REGIME-SWITCHING META-ALLOCATOR (HMM / MARKOV SWITCHING)
--------------------------------------------------------------------------------
What it is
- A probabilistic model (e.g., Hidden Markov Model / Markov-switching) that classifies the market into
  latent regimes (trend, mean-reverting, high-vol, low-vol) and adapts strategy weights, leverage,
  and stop logic dynamically.

Why it’s worth it
- This is “bot-native”: humans are bad at consistently turning strategies on/off across regimes.
- It’s a leverage multiplier on our existing strategies (momentum + mean reversion + stat arb).

Implementation sketch
- Train online (or periodically) on BTC/ETH and/or a market index of perp returns using features like:
  realized vol, trend strength, correlation dispersion, funding stress, breadth.
- Output regime probabilities; map each regime → target allocation & parameter set:
  - Trend/high-vol: weight Momentum higher, widen MR entry, tighten MR exposure.
  - Range/low-vol: weight MR & stat-arb higher, reduce breakout chasing.
- Add hysteresis (avoid rapid flipping) and “cooldown” windows.

Data required
- OHLCV only (works today).


2) ONLINE CHANGE-POINT DETECTION FILTER (CUSUM / PAGE-HINKLEY)
--------------------------------------------------------------------------------
What it is
- Streaming change-detection to identify when the data-generating process shifts (volatility jump,
  trend onset, mean shift). Use this as:
  - a “do not trade MR during trend onset” gate,
  - an early exit trigger when a position’s assumptions break.

Why it’s worth it
- Reduces “death by regime change” which is common in crypto.
- Automated and non-obvious to manage manually (humans lag).

Implementation sketch
- Run CUSUM/Page-Hinkley on returns or z-score/spread residuals.
- If change detected:
  - MR/stat-arb positions: tighten trailing stop / reduce size / exit if confidence high.
  - Momentum: allow earlier entry / allow pyramiding only when regime confirms.

Data required
- OHLCV only (works today).


3) CROSS-SECTIONAL FACTOR LONG/SHORT (PCA / “STAT ARB AS FACTOR NEUTRALITY”)
--------------------------------------------------------------------------------
What it is
- Build a factor model from the returns matrix across the perp universe (e.g., PCA),
  then trade residuals / factor-neutral portfolios (long cheap residuals, short rich residuals).

Why it’s worth it
- More robust than naive correlation pairs; diversifies idiosyncratic mean reversion.
- Naturally portfolio-based (hard for humans to manage).

Implementation sketch
- Compute rolling covariance of returns across selected perps.
- Extract top k PCs (market + sector-like factors).
- For each asset, compute residual return (after projecting onto factors).
- Signal: mean reversion in residuals (z-score), with portfolio construction enforcing factor neutrality.

Data required
- OHLCV across many assets (works today).


4) STAT-ARB UPGRADE: COINTEGRATION + DYNAMIC HEDGE RATIOS (KALMAN FILTER)
--------------------------------------------------------------------------------
What it is
- Improve our current stat-arb by:
  - selecting pairs via cointegration tests (not just correlation),
  - using a Kalman filter to estimate a time-varying hedge ratio,
  - monitoring stationarity breakdown.

Why it’s worth it
- The relationship between two crypto assets drifts; static hedge ratios decay quickly.

Implementation sketch
- Pair selection:
  - Candidate universe from liquidity filters + clustering (correlation/sector tags).
  - Run Engle-Granger cointegration; keep pairs with stable residuals.
- Trading:
  - Use Kalman filter for hedge ratio beta_t.
  - Trade residual z-score; exit on reversion or stationarity failure.
- Risk:
  - Explicit fee/slippage hurdle before entry (stat arb gets killed by fees).

Data required
- OHLCV only (works today).


5) VOLATILITY BREAKOUT WITH VOLATILITY TARGETING (KEEP, TIGHTEN)
--------------------------------------------------------------------------------
What it is
- Detect volatility compression (BBW/ATR percentile), enter breakouts with confirmation,
  but size positions to target a constant risk budget (vol targeting).

Why it’s worth it
- Breakouts can work in crypto, but the key is sizing + avoiding churn.

Implementation sketch
- Setup: BBW < p20 AND realized vol low.
- Trigger: breakout + volume confirmation + market regime not “chop”.
- Stop: ATR-based or structure-based.
- Size: scale notional so expected daily vol contribution is capped (risk parity style).

Data required
- OHLCV only (works today).

6) ORDER-FLOW / MICROSTRUCTURE MODELS (OFI, VPIN, HAWKES)
--------------------------------------------------------------------------------
Status
- Keep as “later” because it requires reliable high-frequency data (trade prints / L2 updates),
  plus latency-aware execution.

What it is
- Use order flow imbalance and/or Hawkes-process-style intensity models to predict short-horizon moves.

Prerequisites
- Websocket pipeline for trades + L2, storage, and careful fee modeling.


7) CROSS-EXCHANGE BASIS / DATA-FUSION ARB
--------------------------------------------------------------------------------
Status
- Keep only as “later”: requires external exchange spot feeds + reliability engineering.

What it is
- Trade perp vs external spot basis when it deviates from norms.

Prerequisites
- External APIs (Binance/Coinbase/etc), latency + rate-limit handling, robust reconciliation.


8) ML / RL SIGNAL ENSEMBLES (LONG HORIZON)
--------------------------------------------------------------------------------
Status
- Keep as “research / later”, not a near-term deliverable.

Why
- Requires dataset curation, offline training, leakage-safe backtesting, and monitoring for drift.

If we do it
- Prefer interpretable models first (regularized logistic / gradient boosting) over deep RL.
- Use it as a meta-layer to weight signals, not as the only signal source.
